**覆盖率解读（为什么 line% 中等偏低）**：

1. **bean 密度高**：台账 240 对象中 177 个是 bean（24 子域）。serde 派生结构体的字段声明行
   计入 llvm-cov 分母，但测试多经服务请求/响应解析路径触达（from_json/Deserialize 宏展开），
   结构体自身声明行与未走到的 `#[serde]` 分支不被计数——bean 层结构性拉低分母（与
   mp/miniapp/common 同因）。
2. **component 88 方法仅 19 个测试触达**：组件服务是 open 的实现重心（trait 88 方法），
   19 个 MockServer 用例覆盖 token 链/route/模板/open account/上传/oauth2 等代表性契约，
   但参数校验分支、重载变体（`get_pre_auth_url` 4 变体等）与其余方法（get_authorizer_option、
   set_authorizer_option、add_to_template、delete_template、fast_register_weapp、tcb 域等）
   未逐一覆盖。
3. **未覆盖热点清单**（静态触达分析，见下表）：
   - **21 个 MISSING 对象**（台账如实标注）：Ma*/Minishop 子域服务接口 9 + 实现 11 +
     PrivacyKeyEnum 1——无 .rs 文件，零覆盖；
   - **桥接层主体实现未被逐方法测试**：`WxOpenMaService`/`WxOpenMpService` 经 trait 默认实现
     继承 ma/mp 全量方法面（jsapi/素材/菜单等），open 侧仅 12 个 bridge 测试验证委托链，
     方法面本体覆盖由 wx-rust-miniapp（81 测试）与 wx-rust-mp（71 测试）承载；
   - **component trait 默认实现未实现方法**（`get_pre_auth_url` 等 Wave 2 未实现分支返回 -99）
     属显式缺口，见语义对照表；
   - **util/json adaptor 与 executor 无独立文件**（台账 DEPENDENCY_REUSED 13 项）：
     线格式内化于 bean serde 与服务实现，无独立覆盖单元；
   - **FastMa 结果 bean 3 个**（O08–O10）实现存在但零测试触达。
